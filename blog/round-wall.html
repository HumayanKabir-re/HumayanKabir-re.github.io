The Round Wall

Where neural cryptanalysis of SHA-256 stops working, and how to prove it

The question

Can a neural network learn to predict the output bits of a cryptographic hash function? The expected answer is no, and the interesting part is not the answer but what it takes to say it credibly.

A negative result is the easiest kind to fake without meaning to. A model that fails to learn looks exactly like a model that was too small, trained too briefly, or fed a buggy dataset. So the work here is mostly not modeling. It is building an experiment where "the model learned nothing" is the only surviving explanation.

SHA-256 makes a good test case because it has a knob. The compression function runs 64 rounds, and you can run fewer. At one round the output is barely mixed and should be learnable; at 64 it should be indistinguishable from noise. Somewhere in between is a boundary, and finding exactly where it sits turns a yes-or-no question into a measurement.

Ground truth you can prove

The first thing that can silently ruin this experiment is a wrong SHA-256. A hand-rolled implementation with a subtle bug produces a function that is not SHA-256, and any result then describes that broken function instead. Worse, the failure is invisible: wrong output still looks like random bits.

So the implementation is round-parameterized over 0 to 64 rounds, vectorized in NumPy over thousands of samples at once, and gated. Before any experiment runs, the full 64-round output is compared bit-for-bit against Python's hashlib, including the message schedule and padding. If it does not match, nothing executes.

That single assertion removes the most likely explanation for a null result before any training happens.

The control that makes a negative result mean something

The second thing that ruins this experiment is measuring the wrong quantity. Suppose an output bit is 1 in eighty percent of samples. A model that ignores its input entirely and always predicts 1 scores eighty percent accuracy. Report that as accuracy and the model looks like it learned something.

So accuracy is never the reported number. For every output bit, a majority-class predictor is fitted on the training split, and the reported quantity is lift: model accuracy minus that trivial predictor's accuracy. A model that has learned nothing scores zero lift no matter how skewed the bits are.

This matters more than it sounds, and the round-2 numbers show why. The MLP reaches 0.8346 accuracy there, which looks impressive until you see the majority baseline is already at 0.7502. The actual learning is the 0.0846 gap, not the 0.83.

The wall

With those two controls in place the result is clean.

Rounds 1 through 4 carry real signal, rising from 0.0784 to 0.0964 lift. At round 5 it does not decline. It vanishes: 0.0004, which is half the noise margin. And it stays vanished through rounds 6, 8, 12 and 16, never once climbing back out.

The noise margin is worth being precise about, because the entire negative claim rests on it. Each round is evaluated on 1,536,000 individual bit-predictions. At an accuracy near 0.5 that gives a 95% margin of ±0.0008. A measured lift of 0.0004 is therefore not a small signal. It is a number that is statistically indistinguishable from zero, and I can say that with an actual interval rather than a shrug.

Two learners, so "no signal" is not "too small a model"

The obvious objection to any null result is that the model was not good enough. The defense is to run two model classes of very different capacity and show they agree.

Below round 5 the two learners behave differently, and sensibly so. The MLP extracts more than the linear probe at every round, and the gap widens as the function gets harder: 0.0124 at round 1, 0.0306 at round 4. That is what you expect when there is genuine nonlinear structure to find and one model can represent more of it.

At round 5 both drop to the same place, and the gap closes to 0.0003. A capacity ceiling would not do that. If the MLP were merely too small, it would keep beating the linear probe by a shrinking but nonzero margin. Instead the extra capacity stops buying anything at all, which is the signature of there being nothing left to buy.

Does the wall move?

One sweep is an anecdote. The project ran several configurations across five phases and a range of architectures, and they do not all agree.

The disagreement below the wall is real and I am not going to smooth it over. Round-4 lift is 0.0964 in the main sweep, 0.0893 and 0.0677 in two runs of the Phase 3 MLP, and 0.0510 under the bootstrapped Blueprint setup. Training length, sample count and estimator differ between them, so the size of the round-4 signal is a property of the experiment as much as of the function.

At round 5 that spread disappears. Every configuration lands between -0.0004 and +0.0004, all of them inside the margin. The finding that survives is not a number, it is a location: whatever you change about the setup, the signal ends after round 4.

That the boundary is a property of SHA-256 rather than of my code is corroborated from outside the project. The strongest published attacks on the compression function reach only the low 30s of rounds and still cost more than brute force. A learned model collapsing at 5 is entirely consistent with a function whose whole design goal is to destroy low-degree structure within a few rounds.

A positive control: Speck32/64

Everything above is a null result, and a null result from an apparatus nobody has seen succeed proves very little. The apparatus might just be broken in a way the hashlib gate does not catch.

So the same machinery was pointed at a cipher that is known to be breakable this way. Gohr's differential distinguisher for round-reduced Speck (CRYPTO 2019) is the reference positive result in neural cryptanalysis, and reproducing it is the control that makes the SHA-256 null credible.

At five rounds the distinguisher reaches 0.7742 against a 0.5 floor, and it still has 0.5742 at six before falling to chance by seven. A second run of the same notebook gave 0.7652 and 0.5497, so the exact figures move a little, but the shape does not.

One more experiment sharpens the contrast. Feeding the network the ciphertext XOR-difference as explicit input features, rather than making it learn to compute that difference internally, lifted five-round accuracy from roughly 0.69 to 0.77 and six-round from roughly 0.52 to 0.60.

That feature would do nothing for SHA-256, and knowing why is the point. It helps on Speck because a differential signal exists in the ciphertext difference at those rounds and the network was wasting capacity reconstructing it. Past round 4 of SHA-256 the output difference is itself uniform, so there is no signal underneath for any feature to expose. The same idea buys a round on one primitive and exactly zero on the other, and being able to predict which before running it is the transferable skill.

The bug that made a model look good

A graph neural network operating on the computation DAG produced accuracy well above everything else in the project. That is the result you want, and it was wrong.

The node features included final-state values from the computation. The target was derivable from those features directly, so the model was not predicting the output, it was reading it. Removing them removed the accuracy, and the GNN fell back in line with every other architecture.

I am including this because it is the most useful thing in the project. Answer leakage does not announce itself. It looks like success, it arrives exactly when you were hoping for success, and the incentive to accept it is strongest at that moment. The reason it got caught is the majority baseline: a result that far above trivial, on a function everything else said was unlearnable, was implausible enough to go looking for a cause. The control that exists to prevent false positives also caught the one that got through.

Why a 1% edge would not have mattered anyway

Suppose the wall had not been quite so clean and some small per-bit edge survived past round 5. It is worth knowing what that would actually be worth against a full 256-bit hash.

Table 1. Advantage over brute force when matching a full 256-bit hash, as a function of per-bit accuracy.

The curve is brutally steep, which cuts both ways. A per-bit accuracy of 0.51 is a 159-fold speed-up, so a tiny edge really would be worth having. But the measured lift past round 5 is 0.0004 with a margin of 0.0008, which puts it below even the 0.5062 row, and that row is only worth 23x against a search space of 2256. The wall is not a near miss.

What this was actually for

The cryptography is a testbed. What the project is really about is the three ways an evaluation lies to you, and it happens to be a domain where all three are unusually easy to expose.

Ground truth can be wrong, so validate the data generator before trusting anything downstream. The metric can flatter you, so measure against the trivial predictor rather than against zero. A single run can fool you, so replicate across seeds and quote an interval you can defend.

Those are the same three failures behind most offline results that do not survive contact with production. Building the baseline that would expose your own result is a habit, and a hash function is a good place to practice it, because it is one of the few settings where you know in advance what the honest answer has to be.
